01 产品概述与范围

1.1 产品定位

面向离散式真空烧结产线的小规模制造运营管理系统，提供生产现场作业协同、简易WMS库存/库位管理、跨工位机器人搬运调度、设备状态集中监控与异常恢复。产品以单台复合机器人连接4台真空烧结炉，避免将现场控制逻辑割裂为多个孤立界面。

1.2 业务目标与成功标准

目标 业务含义 衡量方式（需真实数据）
减少人工转运 工人以备料和异常处置为主，减少炉间反复搬运 单任务人工干预次数 / 人工转运次数
提高任务可追溯性 明确每一笔生料/熟料的当前位置、目标炉及动作阶段 任务状态有据可查比例、库存一致率
降低重复作业风险 异常、重启或PLC轮询时避免重复取放及库存双扣 重复动作事故数、异常恢复成功率
提高协同透明度 统一查看炉位、机器人、缓存及库存状态 平均故障定位时间、任务完成率

1.3 产品边界

纳入本期：生料登记与库位占用、手动指定目标炉、熟料回库/出库、车载暂存位、炉位任务、AGV/PLC/机械臂协同、报警与恢复锁、基础运营报表、角色权限与日志。

暂不纳入本期：完整企业级MES工单管理、采购供应链、财务成本核算、ERP双向同步、全流程条码追踪、AI自动排产、预测性维护模型、无人工授权的自动故障恢复。

1.4 术语

术语 定义
MOM 制造运营管理（本方案仅覆盖轻量化执行/仓储/设备协同能力）
简易WMS 以库存、库位、流转和出入库记录为中心的轻量仓储模块
AGV背包 复合机器人车载3个物料暂存位，非独立库房货位
LM6 / LM7 分别为上下料交换工位和换电工位

2.1 利益相关者

2.2 真实场景约束

  • 4台炉共用1台复合机器人，AGV负责工位移动，机械臂负责取放，PLC管理炉状态/缓存交互，工业相机辅助定位。
  • 工人端不要求扫码入库；目标炉号在HMI中手工选择，系统维护逻辑库存和目标炉归属。
  • 车载背包以3个位为最终业务约束，不沿用最初5层假设；单机械臂/单抓取任务，调度需按资源占用串行处理。
  • LM6为上下料交接与视觉纠偏工位；LM1–LM4炉前按各炉参数执行补偿；LM7用于人工换电。
  • 低电量参考阈值10%；存在单炉维护、全局下班、碰撞恢复锁、PLC重连与重启续作等模式。
  • 旧资料包含PLC端8个生料/8个熟料缓存信号位；这些寄存器缓存数量不直接证明真实WMS货架物理容量。原型用R1–R8/C1–C8作为演示逻辑位，部署需按现场库位重新建模。

03 端到端业务流程

3.1 生产与库存主链路

  1. 备料登记：操作员在HMI选择目标炉F1–F4并将生料放入指定逻辑库存位置，系统生成内部记录并检查空位。
  2. 创建任务：调度读取炉状态、原料可用量、AGV背包空位、电量及维护/安全锁，计算待执行的取料、换料或卸料任务。
  3. LM6领料：AGV到达LM6，经设备握手确认取料动作完成后，库存位置从原料区迁移至车载背包位。
  4. 炉前取放：前往LM1–LM4指定工位；结合视觉核对、PLC状态与机械臂动作确认完成生料装炉及/或熟料取炉。
  5. LM6回库：AGV携熟料返回；经PLC确认卸料后，库存从背包转为冷却缓存区，形成可交接记录。
  6. 人工出库：确认熟料可交接后，操作员执行出库或转运；库存流水保留来源/去向/原因/时间。
  7. 异常分支：碰撞、PLC失联、库位不一致、背包状态不明等情况进入恢复锁，禁止不经核对的动作重发。

3.2 作业类型规则（产品层设计，不等于PLC寄存器枚举）

作业类型 前置条件 设备动作与库存变化 完成条件
只装生料 / LOAD 炉空闲、有对应生料 原料区→背包→炉内 炉内新料确认、任务结束
取熟料并补生料 / SWAP 炉完成、有生料、背包足够 炉内熟料→背包；新料→炉；熟料→冷却 双动作确认且库存一致
只取熟料 / UNLOAD 炉完成、无可用生料或只卸模式 炉内熟料→背包→冷却 炉状态及回库确认
暂停/维护 急停、维修、下班或恢复锁 保留任务、禁止新动作 现场确认后放行

命名提醒 本公开交互原型以 LOAD / SWAP / UNLOAD 标记三类作业。代码中的内部枚举仅用于模拟，非真实 PLC 控制码。

3.3 库存位置转换

逻辑位置模型：RAW（原料区）→ BAG（AGV背包）→ FURNACE（炉内）→ BAG（熟料）→ COOLING（冷却/熟料区）→ OUTBOUND（人工交接）；任何一次位置转换必须以设备动作完成或授权人工确认作为提交条件。

3.4 首炉与特殊模式

新批次首炉：待工艺参数确认后放行。单炉维护：该炉禁派任务，其余炉按资源条件继续。全局下班：不再接新任务，优先处理安全收尾，确保AGV物料和状态可追溯。低电量：优先安全卸载背包物料后进入LM7换电流程。

4.2 FR-001 ～ FR-005：简易WMS详细规则

  • 库存对象：以一份可搬运的烧盒/批次容器为最小逻辑单位；仅在原型演示中生成内部物料ID，不能推断实物具有唯一条码。
  • 登记字段：目标炉号（必填，人工选择）、库位（必填）、物料类型（入库固定为生料）、入库时间、记录人；批次号/工单号为后续可选项。
  • 库存状态：AVAILABLE（可用）、RESERVED（已分配待领）、IN_TRANSIT（车载）、IN_FURNACE（炉内）、COOLING（熟料区）、OUTBOUND（已出库）、EXCEPTION（待核对）。
  • 出入库不允许负库存：任何取料均检查当前占用、目标库位可用、任务版本；人工更正必须通过授权和盘点记录，不直接覆盖历史流水。
  • 库位配置：仓储位数量由现场配置，原型 R1–R8、C1–C8仅作为演示映射；车载B1–B3为项目确认的实际容量约束。
  • 数据一致性：库存当前表与库存事件流水应同一数据库事务提交；通信失败时记录PENDING_CONFIRM并阻断下一动作，不能假定机械已完成。

4.3 FR-006 ～ FR-009：调度与任务管理详细规则

  • 同一炉位最多存在一条未完成的操作性任务；AGV同一时刻仅执行一条活动任务；按照炉完成状态、目标炉库存和路径约束调度。
  • 任务必须包含task_id、目标炉、作业类型、优先级、创建时间、阶段、执行状态、原料位置、背包位置及最近确认步骤。
  • 对已有取放动作采用“命令序号+阶段+设备应答”去重；不允许因为重连或PLC电平保持而重复下发相同物理动作。
  • 电量<10%时拒绝新正常任务，保留当前物料安全策略；换电状态落盘并确保重新启动前检查位置、背包、PLC及急停。
  • 停机/维护、首炉参数未确认、冷却区满、AGV背包满时，系统应提示阻断原因而不是无限重试。

4.4 FR-010 ～ FR-014：设备与异常

  • 监控维度：F1–F4炉状态（空闲、烧结中、完成、维修）、AGV位置和电量、机械臂状态、PLC连接质量、视觉状态、任务阶段。
  • LM6进行XY/Rz偏差识别；LM1–LM4按炉位配置使用Z轴补偿。视觉标识错误、置信区间异常、碰撞或物理状态不明时不得自行放行动作。
  • 恢复锁必须记录发生原因、设备位置、最后确认动作、背包/炉内/库存快照、人工确认人与时间；用户界面应明确“解锁≠已经完成物理恢复”。
  • 参数修改需至少角色授权、输入范围验证、参数生效时间/版本和回滚；本原型只模拟这些过程，不写入控制器。

05 信息架构与页面交互规格

原型采用“运营总览—WMS库存—调度任务—设备管理—异常恢复—运营报表—参数与规则”七个一级导航。真实项目具有Web管理界面；此处提供的是独立制作的作品集静态原型，并非现场已部署系统或历史生产代码。

P02 WMS库存 原料位R、熟料位C、车载B、炉内物料、流水 手动入库、查看库位、熟料出库、导出CSV 满位、空位、位置冲突

5.1 关键交互 I：手动入库

入口：WMS > 人工生料入库。弹窗依次显示目标炉号（F1–F4）、原料空位列表、逻辑物料说明；用户确认后生成库存记录与入库流水。校验：满仓不可提交、库位被占不可覆盖、恢复锁禁止修改、不要求扫码。成功反馈应显示位置与目标炉。

5.2 关键交互 II：创建及推进调度任务

入口：调度任务 > 生成作业任务。选择目标炉后系统计算作业类型并解释约束；新任务入队等待。原型“执行下一步”依次演示：LM6领料→炉前动作→LM6熟料回库。每步更新任务阶段和库存位置，并记录事件；真实生产必须由设备回执触发事务提交。

5.3 关键交互 III：异常锁定与恢复

入口：异常与恢复 > 模拟故障。触发后界面突出安全锁，禁用推进按钮。使用班组长/工程师角色，完成三项核对（安全状态/实物一致/PLC任务阶段），才能恢复演示。操作员角色仅可查看，不可解锁。

5.4 状态文案标准

场景 正向反馈 阻断提示
入库 入库成功；已占用R#；目标F# 库位已满 / 库位被占用 / 恢复锁生效
派单 任务 T-xxxx 已加入队列 炉维护中 / 无匹配生料 / 同炉有待执行任务
作业推进 阶段完成并写入流水 背包不足 / 电量过低 / 冷却位不足
恢复 人工确认通过，继续当前任务 请完成所有核对项 / 当前角色无权限

alarm_event alarm_id, task_id, reason, phase_snapshot, status, assignee 异常锁及人工处置审计
parameter_history key, target, old, new, approver, applied_at Z补偿等参数变更版本化

6.2 数据质量与一致性策略

  • 库存变更采用事件驱动的事务边界：操作开始只设置预留状态，设备动作确认后才能变更当前位置；不可将“已发送命令”当成“物料已移动”。
  • 单份物料不得同时出现在两个有效库位；同一库位容量为1时不能有两份有效物料；炉状态与炉内物料是否存在须一致。
  • 恢复期间以现场实物为最终核验依据，软件可保存冲突快照并要求人工签核；不能以自动对账代替机械臂安全确认。
  • 根据已有SQLite任务持久化经验可采用SQLite作轻量单机存储；如果扩展多客户端/多产线，应评估服务端数据库和事务模型。
  • 演示原型使用浏览器localStorage，不含任何真实 PLC/AGV 接口、远程数据库或账号系统；数据不是生产级持久化。

字段 示例 业务规则

07 系统架构、接口与状态机

7.1 系统分层

表现层：Web管理端/HMI（真实项目工程基础），本作品集单HTML页面作为交互原型；业务层：WMS库存、任务调度、设备管理、告警与参数；集成层：AGV导航SDK、机械臂控制接口、PLC Modbus TCP、工业相机；数据层：SQLite任务与库存状态持久化。

7.2 设备接口与责任边界

接口 方向与作用 重点约束
PLC Modbus TCP 读取炉状态/急停/缓存；写入AGV与PLC握手信号 IP/端口及寄存器映射以现场协议为准
AGV导航 调度层→AGV站点任务；AGV→位置/电量/到位 工位LM1–LM4、LM6、LM7
机械臂动作接口 调度层下发受控动作，读取结果 与安全互锁和机械臂状态核对
工业相机/ArUco LM6二维码确认与XY/Rz测量 视觉异常拒绝盲目纠偏；非深度学习AI
SQLite 存储任务阶段、背包位置、库存与告警 断电完整性、定期备份、恢复核对

7.3 PLC 协议已知示例与限制

已有工程资料中，PLC下发急停、炉位状态等寄存器，调度侧回写车载暂存位信息等。示例应遵循现场已确认的完整点表，并区分“命令、状态、应答和超时”。本PRD不自行创造新寄存器地址，也不把原型里的 LOAD/SWAP/UNLOAD 作业别名写为PLC真实控制码。

7.4 状态机

对象 状态 / 转换 非法/异常转换应对
炉位 IDLE→RUNNING→DONE→IDLE；任一允许入口→MAINTENANCE 烧结中禁止重复装炉；维护中禁派单
调度任务 PENDING→RUNNING(分阶段)→DONE；RUNNING→PAUSED→RUNNING 不可逆动作确认前不推进阶段
库存 AVAILABLE→RESERVED→IN_TRANSIT→IN_FURNACE / COOLING→OUTBOUND 冲突转EXCEPTION并锁定相关任务
设备恢复 READY→RECOVERY_LOCK→MANUAL_CHECK→READY 未完成现场核验禁止解锁
换电 NORMAL→UNLOAD_ONLY→BATTERY_SWAP_WAIT→STARTUP_CHECK→READY 不允许带未知物料直接正常派单

7.5 幂等控制与断点续作

动作调用必须携带task_id + phase_id + command_seq。对同一阶段重复请求返回已处理结果，不得再次触发机械动作；PLC重连后，先读取设备状态并核对“命令是否已被物理执行”，无法确认则锁定待人工复核。数据库需在危险动作前记录意图，设备完成后原子确认业务状态。

类别 指标与要求 验证方法

可靠性 任务/库存状态断电可恢复；关键阶段不能丢失或重复执行 中断注入、重启恢复测试

12.1 AI功能设计原则

“AI辅助运维”是未来产品设想，不是现有真空烧结项目已实现功能。建议先以历史报警、维护手册、PLC点表建立RAG只读知识库；Agent可调用只读的任务/报警/库存查询工具，输出故障候选原因及引用来源。不得直接下发机械运动、急停解除或恢复锁清除指令。

12.2 价值优先级

先解决库存准确、任务协同与异常恢复的确定性问题；在沉淀完整的设备日志、运维SOP及异常样本后，再评估AI模型可带来的故障定位提升。对于硬互锁、PLC同步和机械动作决策，优先使用可验证的状态机和规则引擎，不引入随机生成式控制。
