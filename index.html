01 / THE PROBLEM

设备控制之外，更困难的是业务状态一致

炉位、库存、车载背包与机械动作由不同子系统管理。一个任务如果在现场通信中断、碰撞或重启时丢失阶段记录，可能造成重复取放和库存错账。

01

多炉共享单台设备

4 台炉共用 1 台复合机器人，需要考虑炉状态、物料可用、车载空位与设备互斥。

02

库存与物理位置关联

工人端不扫码、手工选目标炉，必须用逻辑库存与动作确认维护物料位置。

03

异常不能盲目重试

PLC 轮询、断连或机械臂异常会造成状态不确定，需要可追溯的恢复锁和人工核验。

02 / SOLUTION

轻量制造运营管理，而不是“套一个大 MES”

围绕实际工位构建精简业务闭环，优先解决库存、作业和设备状态的同步；高阶报表、企业级接口与 AI 运维作为后续规划。

设计原则：所有库存流转必须以设备完成回执或授权人工确认作为依据；调度逻辑遵循确定性状态机，不让生成式 AI 直接控制危险机械动作。
03 / CORE CAPABILITIES

围绕现场业务组织产品模块

MODULE 01 · WMS

简易仓储与库存追踪

  • 生料登记：目标炉手工选择、库位占用校验
  • 背包 B1–B3、炉内、冷却位之间的位置流转
  • 库存流水、熟料人工出库、异常状态标记
MODULE 02 · WCS

多炉生产任务调度

  • 只装 / 取放 / 只卸三类作业模式
  • 单AGV互斥、同炉防重复派单、任务状态持久化
  • 维护模式、低电量卸载与LM7换电策略
MODULE 03 · DEVICE OPS

设备协同与可视化

  • 四炉状态、AGV站点与电量、PLC通信和报警
  • LM6视觉定位与炉位补偿参数管理
  • Web管理端统一操作（真实操作依赖现场安全控制器）
MODULE 04 · SAFETY / OPS

异常恢复与业务可追溯

  • 碰撞、断线、库存冲突与恢复锁
  • 现场复核后恢复，不重复已确认的物理动作
  • 产品化规划：分级权限、审计与运营指标
